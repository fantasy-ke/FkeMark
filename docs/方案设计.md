# 重元素与大文档渲染优化方案

## 技术方案概述

FkeMark 的大文档瓶颈已经不在 Markdown 解析和保存序列化，而在「整篇文档的重元素一次性上屏」。公式、Mermaid、Excalidraw、Shiki 代码块和小地图都会在块挂载或预览生成时立刻占用主线程和 DOM。优化目标是：首屏和滚动只渲染视口附近的重元素，相同源码不重复计算，并让实时编辑、分栏预览、阅读、演示和导出共用同一套缓存。不更换 BlockNote，不引入新的 Markdown 引擎，也不把 ProseMirror 改成虚拟列表。

成功标准：

- 含大量公式或十余张流程图的文档，打开后主线程不再被全部重元素占满；视口外只保留占位。
- 同一公式、同一张图在模式切换、主题未变、观察器重扫时命中缓存，不再重算。
- 实时输入仍走现有增量序列化，不把重渲染加回按键路径。
- 导出、复制和搜索不能只看到视口里已水合的内容，必须能强制完整渲染。

## 现状与约束

已经做过、本次不重做的部分：

- 实时编辑按键路径只标脏，停顿后按块增量序列化（`WeakMap` 缓存）。
- 大于约 16KB 或 320 行的文档走 Worker 快速解析；超过 320 个块时分片灌入编辑器（先 48，其后每帧 120）。
- 性能敏感文档（≥10 万字符或 ≥600 行）的分栏预览延迟 120ms，但仍是整篇 `markdown-it`。
- Mermaid、Shiki 语言包已懒加载。长代码块默认折叠到 320px。
- 大文档关闭原生拼写检查。

本次确认的真实缺口：

| 环节 | 现状 | 为什么慢、为什么撑不大 |
| --- | --- | --- |
| 公式 | `mathSpecs.ts` 与 `engine.ts` 都用 `katex.renderToString(..., { output: 'htmlAndMathml' })`，挂载即算，无缓存 | HTML + MathML 让公式 DOM 大约翻倍；视口外公式同样同步排版 |
| 分栏公式 | `thirdToHtml.ts` 先输出 `.fk-math` 占位，`applyKatexToHtml` 再用 `DOMParser` 解析整篇 HTML 后逐个替换 | 公式不多也会整篇再解析一次；公式一多就在主线程串行 KaTeX |
| Mermaid | `renderMermaidSvg` 无缓存；实时块 `paint()` 创建即渲染；预览用整树 `MutationObserver` 每 180ms 全量 `querySelectorAll` | `mermaid.render` 在主线程做布局；多图同时启动会排队堵死首屏 |
| Excalidraw | `renderExcalidrawPreview` 同步拼 SVG；预览在 `useLayoutEffect` 里立刻画完全部图 | 内嵌场景 JSON 又大又重，和公式、流程图叠加后 DOM 与解析成本一起涨 |
| 代码高亮 | BlockNote 代码块挂载后即走 Shiki | 分片灌入结束后，视口外代码块仍会高亮 |
| 大文档布局跳过 | `.editor-inner--large-document > *` 等选择器写给旧 TipTap DOM | BlockNote 的直接子节点是整篇 `.bn-block-group`。`content-visibility` 只在元素自身离开视口时跳过后代，整组始终与视口相交，因此这条规则对当前实时编辑基本无效 |
| GPU 开关 | 只给滚动容器加 `will-change` | 不加速 KaTeX、Mermaid 或 SVG，还可能增加显存 |
| 小地图 | 非源码模式把整篇预览 HTML 再挂一份；悬停每个移动事件都 `markdownToHtml` | 大文档等于双倍 DOM，滚动时还在主线程解析片段 |

约束：

- Markdown 源码仍是唯一真相。懒渲染只影响视图，不改变块属性和序列化。
- 导出、演示全屏和「放大查看」必须走完整渲染，不能复用「只水合视口」的 DOM。
- Mermaid 保持 `securityLevel: 'strict'`。
- 不新增渲染库。缓存、队列、视口观察都用浏览器原生能力。
- 实时编辑不能把 `content-visibility` 直接套到 `.bn-block-outer` 上试水。ProseMirror 的选区、坐标和滚动定位依赖块布局，套错会导致光标和查找错位。

## 技术选型

| 类别 | 选择 | 理由 | 不选 |
| --- | --- | --- | --- |
| 编辑器 | 继续 BlockNote / ProseMirror | 往返、选区、自定义块已经接好 | 虚拟列表编辑器，会重写交互 |
| 公式 | 继续 KaTeX，编辑/预览改为 `output: 'html'` | 同一库，DOM 立即减半；`title` / `aria-label` 保留 TeX | MathJax，更重；MathML 双输出只适合导出 |
| 流程图 | 继续懒加载 Mermaid，加缓存和单槽队列 | 布局无法并行，队列比「全部一起 await」更稳 | Worker 版 Mermaid，依赖 DOM，第一期不稳 |
| 白板预览 | 继续现有静态 SVG 预览 | 已经不是完整 Excalidraw 运行时 | 每个块挂载 Excalidraw React 树 |
| 大文档布局 | 预览用块级 `content-visibility`；实时编辑只包重元素内容 | 避开 ProseMirror 测量 | 把现有错误选择器直接改到 `.bn-block-outer` |
| 缓存 | 进程内 LRU，按源码 + 主题/显示模式做键 | 无持久化、无新依赖，模式切换立刻受益 | IndexedDB，首屏用不上，还要处理失效 |

## 架构设计

三条视图共用一个重渲染服务，编辑器文档模型不变。

```
Markdown / BlockNote 块
        │
        ├─ 实时 / 阅读节点视图 ──┐
        ├─ 分栏 / 演示 HTML 水合 ┼─► 视口门闩 ─► 单槽队列 ─► 渲染缓存 ─► DOM
        └─ 导出 / 放大查看 ──────┘                              ▲
               （跳过视口门闩，强制算完）                         │
                                                     KaTeX / Mermaid / Excalidraw / Shiki
```

分层：

- 表现层：节点视图和预览水合只负责占位、进入视口、把结果写入 DOM。
- 调度层：视口门闩决定何时算；队列保证 Mermaid 同时只有一张在布局。
- 计算层：纯函数渲染。相同输入返回缓存字符串，不碰编辑器状态。

关键决策：离开视口后不销毁已渲染 DOM。销毁会导致滚动回跳和重复布局。内存上限用 LRU 控制「保留的 SVG 字符串」和「远离视口的超大 SVG 节点」，而不是每次滚出就拆掉。

## 模块划分

| 模块 | 职责 | 依赖 |
| --- | --- | --- |
| `src/utils/markdown/renderCache.ts` | 小型 LRU。公式、图、白板预览各用独立上限 | 无 |
| `src/utils/markdown/heavyRender.ts` | `observeNearViewport`、单槽队列、优先级（可见优先于预取） | `renderCache` |
| `src/utils/markdown/katexRender.ts` | 统一 `renderKatexHtml(tex, display)`，编辑器和预览不再各写一份 | `katex`、`renderCache` |
| `mermaid.ts` / `excalidraw.ts` | 在现有函数内查缓存；Mermaid 命中缓存时重写 SVG id | `renderCache` |
| `mathSpecs.ts`、`mermaidBlockView.ts`、`excalidrawBlockView.ts` | 挂载时只放占位，靠近视口再绘制 | `heavyRender` |
| `engine.ts`、`useMermaidDiagrams.ts`、`useExcalidrawDiagrams.ts` | 预览不再整篇 DOMParser / 全量扫描后立刻渲染 | `heavyRender` |
| `Minimap.tsx` | 大文档退回源码色条，悬停预览防抖 | `isPerformanceSensitiveDocument` |
| `editor.css` | 只给预览块和重元素内容区补 `content-visibility` | 无 |

不新增设置项。这些是渲染策略，不是用户可开关的实验功能。现有 GPU 开关保持原语义，不把它包装成「公式加速」。

## 接口设计

内部模块接口，不是 HTTP。

### `createRenderCache<T>(limit)`

- `get(key: string): T | undefined`
- `set(key: string, value: T): void`
- `clear(): void`

键：

- 公式：`html\0${display ? 1 : 0}\0${tex}`
- Mermaid：`mermaid\0${dark ? 1 : 0}\0${source}`
- Excalidraw：对场景字符串做缓存，上限要小，因为 SVG 大

上限建议：公式 512 条，Mermaid 32 条，Excalidraw 16 条。超限删最旧。主题切换靠键区分，不整表清空。

Mermaid 缓存不能直接把同一段 SVG 插进两个节点。`marker`、`linearGradient` 的 id 会冲突。命中后按调用序号重写 id，再返回。

### `observeNearViewport(element, onNear, rootMargin = '800px')`

- 元素进入扩展视口时调用一次 `onNear`。
- 返回取消函数，节点 `destroy` 时必须调用。
- 已经在视口内的元素本帧就调用，避免首屏空等。

### `enqueueHeavyRender(task, priority)`

- `priority: 'visible' | 'prefetch'`
- Mermaid 并发槽为 1。公式和 Excalidraw 静态 SVG 不进这个槽，它们是同步字符串，只受视口门闩和缓存约束。
- 节点销毁或源码变化时，任务自行用现有 `renderToken` 丢弃结果，队列不保存文档内容。

### 预览水合

分栏、阅读预览、演示模式统一：

1. Markdown 转 HTML 时，公式、Mermaid、Excalidraw 保持轻占位，不在 `markdown-it` 规则里同步跑 KaTeX / Mermaid。
2. HTML 插入 DOM 后，由一个水合入口按视口排队补渲染。
3. `renderPreviewHtml` 保留给导出。导出调用 `renderKatexHtml` 字符串替换，禁止 `DOMParser` 整篇重解析。

### 导出与搜索

- 导出路径参数 `force: true`，忽略视口，用缓存算完全部重元素。
- 文档内查找继续搜 ProseMirror / Markdown 源码，不搜已渲染 SVG 文本。

## 数据模型

不新增持久化设置，不改 `AppSettings`。

运行时结构：

```
interface HeavyRenderPlaceholder {
  kind: 'math' | 'mermaid' | 'excalidraw' | 'code'
  minHeight: number      // 首次渲染后记下，避免滚动跳动
  state: 'pending' | 'ready' | 'error'
}
```

块属性不变：公式仍是 `tex`，Mermaid / Excalidraw 仍是 `source`。缓存不进入 Markdown。

## 关键设计决策

| 决策点 | 选择 | 理由 |
| --- | --- | --- |
| 先做视口门闩还是先做虚拟列表 | 视口门闩 | BlockNote 必须保留全文档选区模型；虚拟列表会破坏坐标、拖拽和往返 |
| 实时编辑的 `content-visibility` 加在哪 | 只加在 `.katex-render`、`.mermaid-block-preview`、`.excalidraw-block-preview`、代码块 `pre` | 跳过重排，又不动 ProseMirror 测量的块外壳 |
| 预览的 `content-visibility` 加在哪 | 大文档时加在预览根的直接块级子元素 | 预览没有光标坐标，可以跳过视口外整块布局 |
| KaTeX 输出 | 编辑和预览用 `html`；导出若需要无障碍再单独生成 MathML | 屏幕阅读器仍可读 `aria-label` 中的 TeX；双输出是当前公式 DOM 的最大浪费 |
| 滚出视口是否卸载 | 默认保留 DOM，只限制缓存条数 | 卸载会造成高度抖动和返回时再次布局 |
| Mermaid 是否进 Worker | 第一期不进 | 官方渲染依赖 DOM；队列加缓存已经去掉重复布局 |
| 小地图 | 性能敏感文档不用渲染 HTML | 现有源码色条足够表达结构，成本接近 O(行) 且可截断 |
| 预览增量 | 第二期按标题分段缓存 HTML | 第一期先去掉重元素；整篇 `markdown-it` 仍是纯文本大文档的下一瓶颈 |
| 超大文件策略 | 不自动改打开模式 | 源码模式本身更抗大文件，但是否默认切过去属于产品决策，本次不隐含改变 |

## 实现计划

1. 测量基线。用现有 `recordEditorPerformanceOperation` 增加 `math.render`、`mermaid.render`、`excalidraw.preview`、`preview.hydrate`。准备三份夹具：200 个公式、15 张 Mermaid、1MB 普通正文。不先改行为。
2. 抽出 `renderKatexHtml`，两处调用改为 `output: 'html'` 并接入 LRU。补往返测试，确认 `data-tex` 和序列化不变。
3. Mermaid、Excalidraw 渲染函数接入缓存；Mermaid 命中后重写 id。补「同一源码渲染两次，第二次不调用底层 render」的测试。
4. 实时块改为视口门闩：创建时占位，靠近后再 `paint`。`destroy` 取消观察。高度用首次结果写 `min-height`。
5. 预览去掉整篇 `DOMParser`。公式占位保留到 DOM，和水合队列一起补。`useMermaidDiagrams` 不再对每个 `pre` 立刻 `render`，改为可见才入队；观察器只标记脏主机，不每次全量重渲染已缓存的图。
6. 修正大文档 CSS：预览块级 `content-visibility`；实时编辑只包重元素内容。用含光标移动、查找、滚动到标题的测试确认块外壳没有被跳过布局。
7. 小地图在 `isPerformanceSensitiveDocument` 时走源码色条；悬停片段渲染至少节流到一帧。
8. 第二期，仅当基线显示纯文本预览仍超过约 50ms：按一级/二级标题切段，缓存每段 HTML，只重渲染脏段。代码块在折叠且不可见时跳过 Shiki。
9. 验证：`npm test`、`npm run build`、相关 Markdown 往返测试，以及一份多公式、多流程图文档的手动滚动核验。

## 风险与回退

- `content-visibility` 若误加到 `.bn-block-outer`，光标和滚动定位会错。实时编辑路径禁止使用这个选择器；一旦出现错位，只回退 CSS，不影响缓存。
- 懒水合会让「查看页面源码式复制预览 DOM」缺图。导出和放大查看必须走 `force` 路径，并加测试锁住。
- Mermaid SVG id 重写不全时，同页两张图的箭头标记会串。测试要覆盖同页两张相同图。
- 占位高度不准会跳动。首次渲染后记住高度；源码变化时清掉该块高度。
- jsdom 没有 `IntersectionObserver`。测试里注入同步触发的假观察器，不把视口逻辑只留在手工核验。

## 不在本次范围

- 不把实时编辑器换成虚拟列表。
- 不把 Mermaid 放进 Worker。
- 不把 GPU 开关解释为内容渲染加速，也不默认打开它。
- 不改公式、流程图、白板的 Markdown 语法和设置字段。
- 不在第一期做预览分段缓存；那是纯文本体积的第二刀，不应和重元素混在同一次改动里。
