# 使用方法

FkeMark 的使用方式围绕一个原则：**文档仍然保存在本地文件夹里，编辑器只负责更顺手地写、看、整理和发布 Markdown**。

![FkeMark 使用流程](/images/guide/workflow.svg)

## 日常使用流程

| 步骤 | 操作 | 结果 |
| --- | --- | --- |
| 1 | 打开本地文件夹 | 侧边栏显示原有 Markdown 目录结构 |
| 2 | 新建或打开 <code>.md</code> 文件 | 文件保持普通纯文本格式 |
| 3 | 选择 Live / Split / Read / Source 模式 | 在起草、并排检查、校对和源码控制之间切换 |
| 4 | 插入图片、表格、链接或代码块 | 常用 Markdown 内容可以直接组织 |
| 5 | 保存、查看版本历史、导出或发布 | 用本地文件、版本快照、导出格式或文档站继续流转 |

## 推荐写作路径

1. **先搭结构**：在 <code>Source</code> 或 <code>Live</code> 中写标题、列表和段落。
2. **再补内容**：用工具栏插入链接、图片、表格、代码块等高频元素。
3. **分屏检查**：复杂表格、公式或代码较多时，用分屏对照源码和预览。
4. **阅读校对**：切换到 <code>Read</code>，像看成稿一样检查层级和节奏。
5. **稳定保存**：优先保存为 Markdown；导出格式只用于分享、归档或迁移。

## 导入为 Markdown

首次使用时，在桌面应用的 **设置 → 组件** 中从 GitHub 下载并安装文档转换组件。收起首次下载面板后，可点击顶栏的下载图标查看进度。安装包和便携包均不包含转换器。已安装后，组件新版会与主程序一起显示在 **更新中心**；更新组件无需重启。

在“新建”菜单中，选择“导入本地文档…”或“从网址导入…”。文本 PDF 会根据明显的字号差异推断 Markdown 标题；标题和正文同字号时可能无法区分。PNG、JPEG 或 WebP 图片支持简体中文和英文离线识别；扫描版 PDF 不会自动做 OCR。网址导入只读取 HTTP(S) 响应，不运行网页脚本、不读取浏览器登录状态。

对需要登录或由脚本渲染的页面，选择 **新建 → 导入登录后的网页…**，输入 HTTPS 地址，在独立窗口内手动登录并打开目标页面。正文加载后回到编辑器，点击 **转换当前网页**。应用转换的是已渲染的正文快照，不会将表单、Cookie 或浏览器存储交给转换组件，也不会重新下载原网页。捕获成功或取消后，登录窗口及本次会话会关闭。禁止内嵌浏览器登录、要求弹窗验证的网站可能不兼容；需要登录的图片可能无法在 Markdown 中显示。

本地文档可以一次选多个，转换期间也可以继续提交文件或网址。任务按提交顺序逐个转换，单项失败不影响后续任务。中央面板显示转换格式和各项状态；收起后，可点击顶栏的待处理数量重新打开。全部处理完毕后，面板会自动显示结果。每个成功结果打开为独立的 Markdown 标签页，需手动保存。

## 保存与快照

- 保存当前文件时，FkeMark 会在写入前为已保存的文档保留本地快照。
- 需要主动留档时，点击工具栏“版本历史”中的“创建当前快照”。
- 对比历史版本时，可用“上一个差异 / 下一个差异”按钮在变化行之间跳转。
- 如果文件修改非常频繁，可到“设置页面 → 行为”调整每个文件保留的快照次数。

## 文件夹组织建议

| 场景 | 建议目录 |
| --- | --- |
| 项目文档 | <code>docs/</code>、<code>notes/</code>、<code>changelog/</code> |
| 学习笔记 | <code>inbox/</code>、<code>reading/</code>、<code>summary/</code> |
| 博客草稿 | <code>drafts/</code>、<code>assets/</code>、<code>published/</code> |

::: tip
不要把图片、附件和 Markdown 分散到太多地方。建议把图片放在当前文档同级的 <code>assets/</code> 或项目统一的资源目录中。
:::
