## 块操作添加按钮改为插入同语法空块

- 需求：块操作轨道的「添加」按钮此前固定插入空段落，在列表、引用、标题、代码块下方会打断 Markdown 结构；应改为在下方插入一个与当前元素语法相同的空行。
- 实现：
  - `BlockActionRail.tsx` 新增导出 `getSameTypeInsertBlock(block)`：`heading` 返回同级空标题（沿用 `props.level`，缺失时回退 1 级）；`codeBlock` 返回空代码块并保留 `props.language`（缺失时 `text`）；`checkListItem` 返回未勾选空待办；`paragraph` / `quote` / `bulletListItem` / `numberedListItem` 原样返回同类型；`mermaid`、`mathBlock`、`image` 等无行内语法或无法空置的块回退为空段落。
  - 原 `insertParagraph` 改名 `insertSameTypeBlock`，仍保留「插入前展开折叠标题 → 插入后光标落到新块起始并聚焦」的既有行为；插入位置依旧是当前块的 `after`，因此嵌套层级由 BlockNote 自动继承为同级兄弟。
  - 文案同步：`editor.blockActions.add` 中文改为「在下方添加同类型空行」，英文改为 `Add block of same type below`。
- 涉及文件或模块：`src/components/editor/BlockActionRail.tsx`、`src/i18n/locales/zh-CN.ts`、`src/i18n/locales/en.ts`、`tests/block-action-rail.test.tsx`。
- 验证结果：
  - `npx vitest run tests/block-action-rail.test.tsx` 26 个用例通过：新增 `getSameTypeInsertBlock` 的映射与回退断言、空块保存回 Markdown 后仍带同类语法的断言、列表块点击添加按钮插入 `bulletListItem` 的交互断言。
  - `npm test` 73 个套件、526 个用例通过；`npm run build` 通过；`git diff --check` 通过。
  - 界面核验（jsdom 挂载真实 `BlockNoteEditor` + `BlockNoteView` + `BlockActionRail`，真实 hover 后点击添加按钮）：`- Alpha` → `bulletListItem`、`1. Alpha` → `numberedListItem`、`- [ ] Alpha` → `checkListItem`（未勾选）、`> Alpha` → `quote`、`### Alpha` → `heading`（`level: 3` 保留）、ts 代码块 → `codeBlock`（`language: 'ts'` 保留）、普通段落 → `paragraph`。
  - 数据链路核验（真实编辑器插入 → `serializeBlockNoteDocument` 保存 → `parseBlockNoteDocument` 重新解析）：列表、编号、待办、引用、标题、代码块的空行都能原样还原，保存结果分别为 `- Alpha\n-`、`1. Alpha\n2.`、`- [ ] Alpha\n- [ ]`、`> Alpha\n\n>`、`## Alpha\n\n##`、```ts 空代码块。
- 已知限制或未处理的无关问题：
  - 空段落不会被直接序列化器写出（`blockMarkdownWithoutChildren` 对文本块返回空串后由 `serializeBlockList` 跳过），所以 Mermaid、数学块、图片等回退插入的空段落在保存后会消失。这与改动前「只添加一个空行」的行为一致，本次未扩大范围。
  - 大文档（≥16KB 或 ≥320 行）走快速解析器，裸 `-`、`2.`、`##` 会被解析成段落而不是空列表项/空标题（空待办 `- [ ]` 因 `preProcessEmptyChecklistItems` 注入零宽空格不受影响）。手动回车产生空列表项时同样如此，属既有问题，本次只记录不处理。
  - 本机无浏览器自动化环境，未在浏览器/Tauri 实机点击核验，以上界面核验以 jsdom 真实编辑器点击 + 保存/重载往返替代。
  - 工作区同时存在另一会话正在进行的 AI 续写（ghost text）改动，本次提交只暂存本任务的文件与 hunk，未触碰其余修改。

## 双链图谱改为可拖动的动态力导向布局

- 需求（用户反馈）：「现在的双链图谱怎么就是所有文件以一个小圆点组成的一个正方形。就算没有关系应该是那种的动态的小圆球，各自没有关系，有关系通过线链接起来。而每个文章的小圆球应该是分布展开的，可以拖动动态弹性，点击进入文章」。
- 根因（实测复现）：旧实现是一次性算完的 FR 布局 + 固定 800×800 viewBox。两个问题叠加：① 斥力 `k²/d` 是长程力，且只有向心力 `0.02·(center-p)` 与之配平，平衡尺度远大于画布，200 个节点时 170 个被硬性夹在边界上，于是「所有点贴边排成一个方框」；② `preserveAspectRatio="xMidYMid meet"` 把 800×800 的正方形 letterbox 进 498×576 的画布，视觉上就是一个正方形。另外拖动只改静态偏移量（`dragOffsets`），没有物理反馈，松手不回弹。
- 实现：
  - 新增 `src/utils/markdown/linkGraphSimulation.ts`（纯 TS、无依赖、无随机数）：`createLinkGraphSimulation(graph, { width, height })` 返回带 `tick() / positionOf() / pin() / unpin() / reheat() / updateGraph() / resize()` 的物理模型。黄金角螺旋做确定性初始位置；斥力改为 `C/d²` 并加 `3.2·ideal` 截断（只作用近邻，整张图不再被推向画布边缘）；胡克弹簧沿边收敛；云团软边界 `EDGE_SCALE` 把节点按 `cloudRadius(n)` 兜住；位置松弛（`OVERLAP_RELAXATION`）直接推开重叠圆点，保证圆点互不压住；`alpha` 冷却到 `ALPHA_MIN` 即 `tick()` 返回 false，动画循环停机。
  - `cloudRadius(n)` 随节点数从画布内切圆的一半长到满圆，因此小图谱是一团紧凑圆球、大图谱铺满面板，且不再贴边。
  - `LinkGraphPanel.tsx`：删除 `layout`/`dragOffsets` 状态与 `computeLinkGraphLayout` 调用，改为 `requestAnimationFrame` 循环逐帧推进物理，并把坐标**直接写进 DOM**（`transform` / `x1..y2` 不进 JSX），避免 200 节点 60fps 触发 React 重渲染；画布尺寸用 `ResizeObserver` 按真实像素测量，`viewBox` 与像素 1:1，不再 letterbox。
  - 拖动：`pointerdown` 把节点 `pin` 在指针上并 `reheat(0.65)`，其余节点靠弹簧与斥力弹性让位；`pointerup` 保留拖动速度并 `reheat(0.45)`，节点带惯性滑回云团。拖动后的那次 click 仍被 `draggedRef` 吞掉，纯点击才打开笔记。
  - `computeLinkGraphLayout` 与 `linkGraph.ts` 里的 `clampToBounds` 一并删除（被物理模型取代）；`link-graph.css` 的标签字号由 20px 改为 11px（viewBox 不再是 800 单位缩放），节点光标改为 `grab` / `grabbing`。
- 涉及文件或模块：`src/utils/markdown/linkGraphSimulation.ts`（新增）、`src/components/LinkGraphPanel.tsx`、`src/utils/markdown/linkGraph.ts`、`src/styles/link-graph.css`、`tests/link-graph.simulation.test.ts`（新增）、`tests/link-graph.test.ts`、`tests/link-graph.panel.test.tsx`。
- 验证结果：
  - `tests/link-graph.simulation.test.ts` 7 个用例：坐标确定、稳定后圆点不重叠、单节点居中、空图谱不推进、枢纽比孤立节点更靠中心、拖动跟手且松手后离开指针位置、画布变小后夹回范围、重建图谱保留已有坐标。
  - `tests/link-graph.panel.test.tsx` 新增拖动用例（jsdom 里补齐 `getScreenCTM`/`createSVGPoint`）：被拖节点坐标等于指针、相邻节点坐标发生变化、松手后离开指针位置。
  - `npm test` 74 个套件、531 个用例通过；`npm run build` 通过；`git diff --check` 通过。
  - 真实浏览器核验（`Temp/graphcheck` 临时 Vite harness + headless Chrome，用 CDP `Input.dispatchMouseEvent` 发真实鼠标事件，核验后删除）：24 篇笔记时 `bbox 413x413 / canvas 498x578`、`minGap 53.6`、`atWall 0`、`current 1`；按下后节点与指针偏差 0.0px，拖动中枢纽位移 233.2px 且相邻节点被带动 63.9px，松手后离开指针 178.5px 并重新稳定（`atWall 0`、`minGap 51.2`）；拖动不打开笔记、点击 `note-03` 正常打开。120 篇笔记时 `bbox 436x515`、`minGap 18.4`、`atWall 14`，交互同样正常。截图确认：孤立笔记各自成球、有双链的笔记由线连接、枢纽节点更大且居中。
- 已知限制或未处理的无关问题：
  - 图谱稳定后动画循环会停（省 CPU），因此没有「永远漂浮」的待机动画；拖动、刷新、面板缩放都会重新加热。
  - 200 篇上限时节点仍会贴到软边界（`atWall` 十几到几十个），这是密集图谱的自然结果，已不再是「所有点贴边成方框」。
  - 未实现缩放 / 平移 / 框选，也没有把拖动后的坐标持久化；重新打开面板会按物理重新收敛。
  - 布局对初始尺寸敏感：画布尺寸测量完成前不创建物理模型（`canvasSize` 为 null 时跳过），避免用兜底尺寸播种导致最终布局随帧数漂移。
