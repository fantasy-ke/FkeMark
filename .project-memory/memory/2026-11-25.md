## 修复 macOS ARM64 的 OCR 组件构建

- 现象：组件发布运行 `45541456158` 的依赖安装与 `pip check` 均成功，但 ARM64 的四种图片样本和尺寸校验均返回 `conversion_failed`；其余三平台构建成功，发布任务被跳过。
- 根因：检查 PyPI 的 `tesserocr` 2.7.1 ARM64 wheel，扩展引用未随包提供的 Tesseract 与 Leptonica 符号。导入发生在图片尺寸校验之前，导致两类测试同时报转换失败。
- 实现：`scripts/build-converter.cjs` 将两个 macOS 架构统一接入 `converter/build_legacy_ocr.py` 静态源码构建，不安装 macOS wheel；Intel 保持 10.15，ARM64 保持 11.0，Windows 和 Linux 的依赖不变。
- 验证：构建脚本 6 项、Windows 转换器源码测试 26 项通过；WSL 静态构建和 PNG、JPEG、WebP 识别通过。未运行修复提交的 macOS ARM64 原生构建，未移动 `converter-v1` 标签。
