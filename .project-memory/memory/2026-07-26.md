## 1. 删除行号并解除大文档保存阻塞

### 需求
- 删除设置中的“显示行号”功能，同时删除行号渲染实现和对应测试。
- 排查 800 行以上 Markdown 编辑后保存长时间无响应的问题，确认是否存在死循环，并补充能够定位卡顿阶段的日志。

### 实现
- 删除 `showLineNumbers` 设置字段、默认值、设置界面与中英文文案；移除实时、阅读、源码、分栏模式的行号组件、测量、虚拟化样式和专用测试。
- 未发现无界循环。前端原保存链路虽然先让出一次浏览器任务，但随后仍会同步遍历整篇 ProseMirror 文档；改为按最多 64 个顶层块或约 8ms 时间片执行 Markdown 序列化，并在时间片之间让出主线程。
- 分片序列化期间继续输入会使旧修订结果失效；旧结果只记录日志，不覆盖规范 Markdown，再自动处理最新修订，避免保存或切换视图使用陈旧内容。
- 将 Tauri `write_file_command` 改为异步命令，并通过 `spawn_blocking` 执行旧文件读取、版本快照和最终文件写入，避免同步磁盘操作阻塞 WebView 命令主线程。
- 版本快照由两次目录扫描减少为一次，创建快照后复用同一列表完成数量裁剪。
- 保存日志新增 `save.started`、`save.content-flush.started`、`save.disk-write.started` 和 8 秒阶段卡顿记录；Rust 返回历史目录初始化、旧文件读取、快照、最终写入和总耗时。超过 8 秒时提示用户导出性能日志，不自动强制关闭软件，避免未保存内容丢失。

## 2. 按 Tolaria 架构重写实时编辑渲染

### 需求
- 研究并按 refactoringhq/tolaria 的 Markdown 编辑架构重写实时编辑渲染，解决约 800 行文档输入、切换分栏和保存时主线程长时间无响应的问题。
- 保留可定位解析、分块应用、序列化和保存阶段的性能日志，并明确新渲染器暂不兼容的自定义能力。

### 实现
- 将实时编辑器替换为应用生命周期内复用的 BlockNote 实例；实时、阅读、源码和分栏切换时不销毁编辑器 DOM。
- 输入事件只标记脏状态，停止输入 1500ms 或保存时才执行一次直接块序列化；保存刷新前先让出一个浏览器任务，避免同步阻塞点击和视图切换。
- 320 行或 16KB 以上 Markdown 优先交给 Worker 快速解析；快速解析器不支持的语法回退到 BlockNote 解析器。
- 320 个块以上先应用 48 个块，再按每帧 120 个块追加，应用期间临时禁止编辑，并可中止过期任务。
- 增加文档块缓存和基于块对象的序列化缓存，标准块不再经过 HTML 中转；Front Matter 与 Wiki 链接继续往返保存。
- 增加 BlockNote 解析、分块应用、序列化和 Markdown 刷新日志；既有保存日志继续区分内容刷新、磁盘写入和总耗时。
- 大文档应用完成后再次同步 DOM 属性，确保从源码切回实时编辑时浏览器拼写检查仍保持关闭。

## 3. 修复安装版首页 TipTap 初始化崩溃

### 现象
- 开发模式可正常使用，但安装版启动后停留在启动页，无法进入主页。
- 生产控制台首先出现 `Cannot read properties of undefined (reading 'empty')`；仅合并 BlockNote 后又变为 `Cannot access 'PluginKey' before initialization`。

### 根因
- Vite 的 `manualChunks` 将 TipTap、ProseMirror 与 BlockNote 的其他直接依赖拆进相互导入的生产 chunk。
- 生成的 `vendor` 与 `tiptap-vendor` 形成循环 ESM 初始化，导致 `RopeSequence` 或 `PluginKey` 在静态初始化完成前被读取。开发模式不走同一套生产分包，因此未暴露该问题。

### 修复
- 删除自定义 `manualChunks`，与 Tolaria 的 Vite 构建配置保持一致，交给 Rollup 自动维护依赖初始化顺序。
- 保留现有动态导入形成的自然分包，不再维护容易遗漏间接依赖的编辑器包名清单。

### 验证结果
- 修复前已用生产构建稳定复现首页崩溃；修复后生产预览可进入完整主页，控制台不再出现 TipTap/ProseMirror 初始化异常。
- `npm test`：通过，30 个测试文件 / 218 个测试。
- `npm run build`：通过，2869 个模块完成生产构建。
- Tauri release 程序本体 `src-tauri/target/release/FkeMark.exe` 编译成功；NSIS 安装器阶段因下载 NSIS 工具连续超时而未完成，不是前端编译失败。
- `git diff --check`：通过；`vite.config.ts` 为 43 行。

### 已知限制
- 自动分包后的主入口约 2.46MB，构建仍有超过 600KB 的非阻断警告；当前优先保证安装版稳定启动。后续若重新做依赖分包，必须先增加生产 chunk 循环依赖检查并验证安装包。
- 根目录仍有一份旧版 Tauri 配置，会使直接执行根目录 `npm run tauri:build:nsis` 报配置格式错误；本次未修改该无关问题。
