## 侧边栏文本搜索与 Ctrl+P 快速打开文件

- 需求：① 检查项目全局文本搜索，在侧边栏加入可快速搜索文本内容的入口，且不能是全量硬搜，需要做优化处理；② 增加 Ctrl+P 快捷键搜索当前打开目录的文件，点击在当前窗口打开。
- 现状核实：`Ctrl+p` 其实**已经**绑定 `palette` 命令（`src/utils/keymap.ts`），命令面板的「文件」标签页也已支持按当前目录搜索并点击开标签，因此需求 ② 主要是修缺陷而非从零开发。真正的缺陷是 `CommandPalette` 的 `activeTab` 在面板关闭后仍然保留，导致 Ctrl+P 会落到上次停留的标签页，而不是固定进入文件页。
- 后端优化（原实现为单线程全量 `fs::read_to_string` 扫描，无缓存、无结果上限、不区分二进制文件）：
  - 新增 `src-tauri/src/file_system/search_index.rs`：按根目录缓存文本内容，用「修改时间 + 文件大小」判断缓存是否有效，重复搜索只做一次目录遍历与 stat；建立索引时跳过含 NUL 字节的二进制文件与超过 2 MB 的超大文件；切换根目录时重建索引；提供 `invalidate_index`（批量替换后整体失效）与 `invalidate_path`（单文件保存后精确失效）两级失效入口。
  - `search_in_files` 改为在索引内容上扫描：文件先按路径排序再分片，用 `std::thread::scope` 并行（并行度取 CPU 核心数、上限 8），并按分片顺序合并结果，因此输出顺序与原来的单线程遍历完全一致。
  - 新增结果上限：单文件 50 条、单次搜索 500 条，避免重复度高的文件淹没其它文件的结果，并限制跨进程传输体积。
  - `write_file_command` 保存成功后调用 `invalidate_path`，`replace_in_files` 写入成功后调用 `invalidate_index`。
- 前端：
  - 新增 `src/components/SidebarSearchPanel.tsx`：文件树顶部搜索框，300ms 防抖 + 请求号丢弃过期响应，按文件分组展示命中行号与高亮片段，点击回调打开文件并跳到对应行；没有搜索词时原样渲染文件树（通过 `children` 传入）。
  - `Sidebar.tsx` 在「文件树」标签页顶部接入该面板，新增 `folderPath` 与 `onSearchResultOpen` 两个可选 props；`AppLayout`/`App` 传入 `currentFolderPath` 与 `handleSearchResultClick`（复用命令面板已有的跳转逻辑）。
  - `CommandPalette` 新增 `initialTab` prop，每次打开时重置到该标签页；`App` 在 Ctrl+P 时显式设为 `files`，修复标签页不确定的问题。
  - i18n 新增 7 条中英文文案；`src/styles/sidebar.css` 新增搜索框与结果列表样式，全部使用既有语义 token。
- 涉及文件或模块：`src-tauri/src/file_system/search_index.rs`（新增）、`src-tauri/src/file_system/search.rs`、`src-tauri/src/file_system.rs`、`src-tauri/src/lib.rs`、`src/components/SidebarSearchPanel.tsx`（新增）、`src/components/Sidebar.tsx`、`src/components/CommandPalette.tsx`、`src/app/AppLayout.tsx`、`src/App.tsx`、`src/i18n/locales/zh-CN.ts`、`src/i18n/locales/en.ts`、`src/styles/sidebar.css`、`tests/sidebar.search.test.tsx`（新增）、`tests/command.palette.test.tsx`（新增）。
