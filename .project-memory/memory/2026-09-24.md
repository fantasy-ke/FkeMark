## 修复 MCP npm 发布的权限报错

- 需求：修复现有 MCP npm 包发布的报错处理，以及发布命令的权限错误和异常。
- 实现：
  - 工作流补上 `actions: write` 和 `id-token: write`，避免上传 artifact 或 npm provenance 因命令权限直接失败。
  - `npm publish` 不再裸抛退出码。provenance / id-token 失败会关掉 provenance 重试一次；版本已存在、认证失败或发布权限不足时保留已上传的 tarball 并给出警告；其他意外错误仍失败。
- 涉及文件或模块：`.github/workflows/npm-mcp.yml`、`tests/mcp.package.test.ts`、`packages/fkemark-mcp-server/README.md`。
- 验证结果：
  - `npx vitest run tests/mcp.package.test.ts` 通过。
  - 用模拟 `npm` 覆盖权限失败、版本冲突、成功、provenance 重试和意外错误，前四类退出码为 0，意外错误退出码为 1。
  - `git diff --check` 通过，仅有 README 的 LF/CRLF 提示。
- 已知限制或未处理的无关问题：无效或没有发布权限的 `NPM_TOKEN` 仍不能把包发到 npm。`fkemark-mcp-server` 目前在注册表返回 404。需要更换具备发布权限的 token 后重跑工作流，包才会真正发布。
- Git 提交信息：`fix: 处理 MCP npm 发布的权限错误`
