## 拆分 vendor 兜底分包，消除大 chunk 警告与首屏膨胀

- 需求：生产构建提示 `dist/assets/vendor-70d5ca71.js 1,421.35 kB` 超过 1000 kB 阈值，需要修复该警告。
- 排查：给 `manualChunks` 加构建期模块统计，按包汇总渲染字节后发现，兜底 `vendor` 中 388 kB 是 `@emoji-mart/data`（BlockNote 表情面板按需加载的数据包），57 kB 是 Shiki 的 JavaScript 正则引擎（oniguruma-to-es、oniguruma-parser、regex 系列），其余 14 个包渲染字节为 0。兜底把「只被懒加载引用的包」和「首屏共享依赖」合并进同一个 chunk，而该 chunk 被 `index` 静态引用，导致表情数据被首屏提前加载。
- 实现：保留 `vendor` 兜底规则，改为把兜底内容按「加载时机 + 消费者家族」拆成独立分组：新增 `vendor-mermaid-diagram`、`vendor-mermaid-d3`、`vendor-mermaid-runtime`（mermaid 私有依赖，拆出后仍是懒加载）、`vendor-shiki-engine`、`vendor-emoji-data`（懒加载）；并将 Mantine 运行时依赖归入 `vendor-ui`，`fast-equals` 归入 `vendor-tiptap`，`devlop`、`is-plain-obj` 归入 `vendor-unified`。拆分依据是加载时机而非体积。
- 涉及文件或模块：`vite.config.ts`。
- 验证结果：`npm run build` 通过且无大 chunk 警告；最大 JS chunk 为 `ruby-*.js` 878.8 kB（Shiki 懒加载语法包），无任何 chunk 超过 1000 kB。首屏静态 JS 由 4100.7 kB 降至 2759.9 kB。`vendor` 兜底 chunk 不再产生（规则保留，当前无模块命中），也没有留下空壳 chunk。`vendor-emoji-data` 388.1 kB 与 `vendor-mermaid-*`（691.4／163.1／104.4 kB）均在懒加载侧。dist 静态 import 图扫描：未发现循环依赖。headless Chrome 打开预览服务：应用外壳完整渲染，无 chunk 初始化错误；实测 mermaid 的 flowchart、sequence、pie、classDiagram、stateDiagram 均渲染出 SVG，表情数据懒加载分块可正常载入。`npm test`：63 个套件 / 406 个用例通过，退出码 0（含工作区中他人正在开发的文件树相关用例）。`git diff --check` 通过；活跃代码文件未超过 800 行。
- 已知限制或未处理的无关问题：`chunkSizeWarningLimit` 仍为 1000 kB，用于容纳 Shiki 的 Ruby/C++ 懒加载语法包，本次未调整。`vendor-mermaid-diagram` 691.4 kB 是最大的 vendor chunk，仍在阈值内且为懒加载，未继续细分。`src-tauri/Cargo.toml` 以及工作区中他人未提交的文件树改动未纳入本次提交。
- Git 提交信息：`build: 拆分 vendor 兜底分包以消除大 chunk 警告`
