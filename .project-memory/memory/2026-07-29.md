## 修复 Android 安装包签名与产物校验

- 需求：修复移动端 APK 安装时出现 `packageinfo is null`、安装包被识别为未签名的问题，并检查流水线是否仍会发布错误 Android 产物。
- 根因：开发版与正式版 Android 构建均未向 Gradle 配置发布签名；产物收集还会递归获取生成目录中的任意 APK/AAB，存在把未签名或中间产物上传到 Release 的风险。
- 实现：
  - 新增 `scripts/configure-android-signing.cjs`，在 Android 项目初始化后将仓库密钥环境变量写入生成的 Release 签名配置，并把 Base64 keystore 解码到生成目录；密码只从环境变量读取，不写入 Gradle 文件。
  - `scripts/tauri-android.cjs` 在执行 Android Release 构建前强制配置签名；密钥或生成项目缺失时直接失败，避免继续产出未签名包。
  - 开发版和正式版流水线接入 `ANDROID_KEY_ALIAS`、`ANDROID_KEY_PASSWORD`、`ANDROID_KEY_BASE64` 三个 GitHub Secrets，并在上传前使用 `apksigner verify --verbose --print-certs` 校验 Release APK。
  - Android 产物收集范围限制到 `app/build/outputs` 下的 Release APK/AAB，避免上传调试、未签名或其他中间产物；生成的 keystore 已加入 `.gitignore`。
  - 增加签名注入、密码不落盘、密钥忽略、流水线密钥传递、APK 签名校验和 Release 产物筛选回归测试。
- 涉及文件：`scripts/configure-android-signing.cjs`、`scripts/tauri-android.cjs`、`.github/workflows/dev.yml`、`.github/workflows/release.yml`、`.gitignore`、`tests/mobile.platform.test.ts`。
