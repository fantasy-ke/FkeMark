## 修复 Android 构建路径与移动端审查问题

- 需求：修复 GitHub Actions 执行 `npm run tauri:android:build` 时找不到仓库 `package.json` 的问题，并仅处理 OpenCodeReview 报告中 Medium 及以上问题。
- 根因：Tauri 的 `beforeBuildCommand` 与 `beforeDevCommand` 实际从仓库根目录执行，Android 覆盖配置中的 `npm --prefix ..` 会错误切换到仓库父目录。
- 实现：
  - 将 Android 前置命令改为仓库根目录可直接执行的 `npm run build` 与 `npm run dev`，并为包装脚本补充非零退出码日志。
  - 为开发版和正式版 Android 作业增加 60 分钟超时、完整 Git 历史和 Rust 第三方 Action 的 commit SHA 固定；发布作业在 Android 构建失败时仍可发布已成功的桌面产物。
  - 修正开发版 Android 产物重名处理，使用递增序号避免扩展名被误作冲突后缀。
  - 新增响应式移动运行时 Hook，并同步更新根节点 `mobile-runtime` 类；收敛移动端文件抽屉与 AI 抽屉的互斥开关逻辑。
  - 补充移动文档栏可访问状态、`vh` 回退，合并重复移动端 CSS 规则，并调整底部操作栏层级避免遮挡设置面板。
- 涉及模块：`.github/workflows/`、`scripts/tauri-android.cjs`、`src-tauri/tauri.android.conf.json`、`src/app/AppLayout.tsx`、`src/hooks/useMobileRuntime.ts`、移动端组件与样式、移动端测试。
- 验证：
  - `npm test -- tests/mobile.platform.test.ts tests/mobile.layout.test.tsx`：10 项通过。
  - `npm run build`：通过。
  - `cargo check --manifest-path src-tauri/Cargo.toml`：通过。
  - `cargo test --manifest-path src-tauri/Cargo.toml`：22 项通过。
  - 使用 Android 覆盖配置执行桌面无打包构建时，`beforeBuildCommand npm run build` 已从仓库根目录成功完成；后续因该验证组合找不到桌面调试二进制而停止，不属于 Android 前置命令问题。
  - 在 390×844 的生产预览中核验移动端底部操作栏、文件/AI 抽屉互斥、设置层级，并在调整到 1024×768 后确认移动运行时样式会自动退出。
