## 支持 PR 自动代码审查评论

- 需求：保留 `dev` push 的 OpenCodeReview 提交报告，同时在有人提交 PR 时自动审查并向 PR 发送评论。
- 实现：
  - 在 `.github/workflows/code-review.yml` 新增 `pull_request_target` 的 `opened`、`reopened`、`synchronize` 和 `ready_for_review` 触发，草稿 PR 不执行审查。
  - 保留 push 场景的 commit comment，并把 job 权限收敛到 `contents: write`。
  - 新增 PR 审查 job，固定 OpenCodeReview `v1.7.17` 对应的 commit，仅授予 `contents: read` 和 `pull-requests: write`；Action 使用 Git base/head 差异审查，不检出或执行 PR 代码，适配 fork PR 的 AI 评论场景。
  - PR 审查复用 `AI_API_URL`、`AI_API_KEY`、`AI_MODEL`、`AI_TIMEOUT_MS`、`OCR_USE_ANTHROPIC` 和 `OCR_VERSION`，其中 `AI_TIMEOUT_MS` 从毫秒转换为 Action 需要的秒。
  - 增加工作流测试，覆盖 PR 触发、job 条件、最小权限、Action 固定版本、增量评论配置，以及未直接 checkout PR head。
- 涉及文件：`.github/workflows/code-review.yml`、`tests/code-review.workflow.test.ts`、`.project-memory/memory/2026-07-29.md`。
- 验证：

  - `npm test`：38 个测试文件、254 个测试通过。
  - `npm run build`：通过。
  - `actionlint v1.7.12 .github/workflows/code-review.yml`：通过。
  - `git diff --check`：通过；活跃代码文件没有超过 800 行。
- 已知限制：`pull_request_target` 工作流需要存在于默认分支 `main` 才会触发 PR 审查；本地无法直接验证 GitHub PR 评论实际发送效果，首次贡献者 PR 是否需要人工批准取决于仓库 Actions 设置。
