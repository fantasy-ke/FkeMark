## 1. 修复渲染视图行号定位与空行编号

### 需求
- 修复实时编辑、阅读和分栏预览中，标题等高块渲染后占用多个连续行号、后续行号错位的问题。

## 4. 重构长文档实时编辑渲染链路

### 需求
- 修复 Markdown 内容过多时，实时编辑继续输入后渲染响应可能阻塞至少 10 秒的严重性能问题。
- 重构输入事务的渲染与统计方式，避免每个按键重复遍历、序列化或布局整篇文档，并提交到 Git。

### 实现
- 将 TipTap 默认的 `CodeBlockLowlight` 替换为基础 `CodeBlock` 与自定义增量高亮插件；通过 `getChangedRanges()` 获取 transaction 变更范围，映射既有 Decoration，仅重新扫描和高亮受影响的代码块，普通段落输入不再遍历全文代码块。
- 长文档输入的状态栏行数统计改为 300ms 合并延迟，连续 transaction 不再同步执行整篇 ProseMirror 文档的 `textBetween()`。
- 长文档渲染行号先保留源 Markdown 行数兜底布局，再以 400ms 合并延迟执行实际 DOM 几何测量；MutationObserver、ResizeObserver 和 TipTap update 不再在每次输入时立即触发全文布局读取。
- 仅在超过 100000 字符的实时编辑模式启用 `content-visibility: auto` 与 `contain-intrinsic-size`，让 WebView2 优先布局视口附近块；同时关闭原生全文拼写扫描，避免浏览器在每次输入时检查整篇内容。短文档、阅读模式和已有保存/刷新语义保持不变。
- 将不再使用的 `@tiptap/extension-code-block-lowlight` 依赖替换为直接使用的 `@tiptap/extension-code-block`。

## 6. 统一所有视图模式的行号处理

## 9. 重写实时编辑 Markdown 渲染与保存管线

### 需求
- 700～800 行以上的 Markdown 在实时编辑输入后，保存文件会长时间卡住；输入后切换到分栏视图也会再次无响应。
- 参考 `refactoringhq/tolaria` 的 Markdown 编辑与保存方式，重写渲染、快照、模式切换和保存链路，并补充可导出的性能日志。
- 保留 FkeMark 已有的 Front Matter、列表标记、任务列表、表格分隔、图片尺寸、数学公式、Wiki 链接、文档标签和脚注等自定义语义；无法无损支持的内容必须明确记录。

### 实现
- 移除实时编辑器原有的 `getHTML()` + Turndown 全文转换管线，新增 ProseMirror 文档到 Markdown 的直接序列化器；按顶层块使用 `WeakMap` 缓存，只重新序列化结构发生变化的块。
- 输入事务只标记 dirty、记录修订号并合并行数统计；停止输入 1.5 秒后生成一次规范 Markdown 快照。保存、导出和实时模式切换使用带原因标记的异步快照刷新，在执行重计算前先让浏览器完成一次界面更新。
- 分栏预览不再复用实时编辑器 HTML，统一从规范 Markdown 快照执行 Markdown→HTML 和预览装饰，避免模式切换时与 HTML→Markdown 转换争抢主线程。
- 保存流程提取到 `useDocumentSave`：先取得同一份 Markdown 快照，再异步写盘并更新标签缓存；通过请求编号、文档修订号和活动标签检查，避免写盘期间继续编辑后把旧快照错误标记为已保存。
- 性能日志新增 `editor.markdown.serialize`、`preview.markdown-to-html`、`preview.decorate-html`、`preview.total`、`save.content-flush`、`save.disk-write`、`save.total` 等阶段，并记录缓存命中、回退节点、被省略节点、待处理时长和陈旧保存结果；日志不包含正文或完整文件路径。
- Wiki 链接选择器回归测试改为等待 1.5 秒空闲快照，符合新的合并更新语义。

### 已知限制或未处理的无关问题
