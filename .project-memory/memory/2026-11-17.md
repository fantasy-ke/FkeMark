## 重新打开应用时恢复上次打开的标签页

- 需求：优化打开历史，重新打开软件时恢复上次打开过的文件与文件夹；用户手动关闭全部标签后，下次启动不再恢复文件。
- 实现：
  - 会话保存为应用数据目录下的 `session.json`（`dirs::config_dir()/FkeMark/session.json`，与 `settings.json` 同级），不再依赖 WebView 的 localStorage；Rust 侧新增 `src-tauri/src/session.rs` 与 `load_session_state` / `save_session_state` / `clear_session_state` 命令。写盘采用「临时文件 + 重命名」的原子替换，文件损坏时按无会话处理，不阻断启动。
  - 新增会话持久化模块 `src/app/session.ts`：只保存文件夹路径、已落盘标签页路径和当前标签路径（未命名标签无法恢复，直接忽略）；对损坏数据、非法路径、重复路径做归一化，最多保存 50 个标签。桌面端写入串行化，避免快速切换标签时写入乱序；仅标签路径/当前标签/文件夹变化时才写盘（按序列化签名去重），输入内容不会触发文件写入。
  - 浏览器调试环境回退 localStorage；首次读取时若会话文件不存在，会把上一版本保存在 localStorage 的会话自动迁移到文件并清理旧键。
  - 新增 `src/app/useAppSession.ts`：主窗口在设置加载完成后读取会话，先静默打开上次文件夹（`scanFolder` 的 `silent` 选项），再并发读取标签文件并一次性恢复；设置加载完成、或恢复流程结束后才允许写回会话，避免启动初期的空标签状态覆盖已保存会话。
  - 会话写入是持续行为：任意标签增删、切换当前标签或打开文件夹都会更新会话；手动关闭全部标签后写入的会话没有标签路径，因此下次启动不会恢复文件（仍会恢复文件夹）。
  - 新增 `useAppTabs.restoreTabs` 批量创建并激活标签，避免逐个 `switchToTab` 产生的中间状态；同时把最近文件列表持久化到 `fkemark:recentFiles`，重启后侧边栏历史仍可查看。
  - 二次启动若带系统“打开方式”文件参数或任务栏最近文件夹参数，优先打开显式目标，跳过旧会话恢复。
  - 新窗口（`win=secondary`）不读取也不写入会话，避免多个窗口互相覆盖。
  - 为控制 `App.tsx` 行数，把系统启动打开文件逻辑抽到 `src/app/useStartupOpenFiles.ts`，把文件夹扫描抽到 `src/app/useFolderScan.ts`，行为保持不变。
- 涉及文件或模块：`src/App.tsx`、`src/app/session.ts`、`src/app/useAppSession.ts`、`src/app/useAppTabs.ts`、`src/app/useStartupOpenFiles.ts`、`src/app/useFolderScan.ts`、`src-tauri/src/session.rs`、`src-tauri/src/lib.rs`、`tests/session.restore.test.tsx`。
- 验证结果：
  - `npm test`：79 个测试文件、574 个用例全部通过（新增会话恢复用例，覆盖文件会话恢复、手动关闭全部标签、显式启动目标优先、localStorage 迁移、浏览器回退和会话数据归一化）。
  - `npm run build` 通过；`npx tsc --noEmit` 通过；`git diff --check` 通过。
  - `cargo check --manifest-path src-tauri/Cargo.toml` 通过；`cargo test --manifest-path src-tauri/Cargo.toml` 58 个用例通过（含 6 个会话文件规范化用例）；`rustfmt --check src-tauri/src/session.rs` 通过。
  - `App.tsx` 由 823 行降到 795 行，改动涉及的其余代码文件均小于 800 行。
- 已知限制：未命名标签的未保存内容不会持久化，重启后无法恢复；恢复在窗口显示后异步完成，文件较多时可能短暂看到欢迎页；恢复过程静默跳过已删除或无权限的文件，不提示用户。
